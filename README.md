# پنل و کلاینت ریموت RustDesk دانشگاه

مخزن شامل دو بخش مستقل است:

- `panel/`: پنل وب، نصب، بکاپ/ریستور و به‌روزرسانی پنل
- `client/`: کلاینت واسط ویندوزی و Agent ثبت مشخصات رایانهٔ مقصد

نسخهٔ پنل در `panel/VERSION` نگهداری می‌شود. هر نسخهٔ جدید باید این مقدار را افزایش دهد.

## نصب پنل روی Ubuntu

فایل‌های مخزن را در Ubuntu دریافت و نصب کن (پورت پیش‌فرض ۸۷۶۵ و IP پیش‌فرض 172.16.2.99 است؛ اگر IP سرور فرق دارد، مقدار `PANEL_BIND` را هنگام نصب بده):

```bash
git clone https://github.com/ahmadimahdi111-rgb/Rustdeskanel.git
cd Rustdeskanel/panel
sudo bash install.sh
```

حساب مدیر و کلید Agent در فایل فقط‌خواندنی `/root/rustdeskpanel-login.txt` نوشته می‌شوند. نام کاربری مدیر `admin` است. نصب‌کننده پنل قبلی `mizyar-panel.service` را متوقف می‌کند و collector نسخهٔ قبلی را برای نمایش وضعیت Docker دست‌نخورده می‌گذارد.

## کلاینت ویندوز

در ویندوز فایل `client/HCU-RemoteClient.hta` را اجرا کن و با همان حساب پنل وارد شو. شناسه را در اولین اتصال وارد می‌کنی؛ کلاینت آن را به فهرست همان کارشناس اضافه می‌کند. دفعات بعد از فهرست انتخابش کن. RustDesk باید جداگانه نصب و با ID Server، Relay Server و کلید عمومی دانشگاه تنظیم شده باشد. این کلاینت واسط Windows است و RustDesk نصب‌شده را برای اتصال باز می‌کند؛ فایل اجرایی بازکامپایل‌شدهٔ RustDesk نیست.

برای نمایش خودکار نام و IP سیستم مقصد، روی هر مقصد `HCU-DeviceAgent.ps1` را اجرا و کلید Agent را وارد کن. برای نصب Task Scheduler با دسترسی مدیر اجرا کن:

```powershell
powershell -ExecutionPolicy Bypass -File .\HCU-DeviceAgent.ps1 -InstallTask
```

## پشتیبان‌گیری

مدیر از بخش «پشتیبان‌گیری» نسخهٔ محلی SQLite می‌گیرد؛ پشتیبان‌گیری ابری در این پنل وجود ندارد. بازیابی فقط فایل SQLite سالم و دارای جداول پنل را قبول می‌کند؛ پیش از جایگزینی، نسخهٔ خودکار اطلاعات فعلی در `/var/lib/rustdeskpanel/` ساخته می‌شود. نسخه‌های پیش از به‌روزرسانی هم در `backups/` نگهداری می‌شوند.

## به‌روزرسانی از پنل

نسخهٔ فعلی ۳.۲.۰ است و در رابط به‌شکل «نسخهٔ ۳.۲» نمایش داده می‌شود. پنل برای بررسی، `panel/VERSION` شاخهٔ `main` را از GitHub می‌خواند. به‌روزرسانی با یک launcher محدود sudoers در unit جداگانه اجرا می‌شود تا راه‌اندازی مجدد پنل، فرایند به‌روزرسانی را متوقف نکند. سرور باید به GitHub دسترسی خروجی داشته باشد. فایل‌های env، گواهی TLS و پایگاه‌داده از مخزن دریافت یا جایگزین نمی‌شوند. برای ارتقای یک‌باره از بستهٔ ZIP از `panel/upgrade.sh` استفاده کنید؛ این اسکریپت تنظیم sudo و سرویس را نیز برای به‌روزرسانی آنلاین اصلاح می‌کند.

## محدودیت گزارش

ثبت نشست از کلاینت سازمانی انجام می‌شود. اگر کارشناس RustDesk را مستقیم باز کند، این پنل نشست را نمی‌بیند. RustDesk OSS به‌تنهایی هویت سازمانی را enforce نمی‌کند. برای جلوگیری از دور زدن ثبت، استفاده از کلاینت سازمانی باید در رویهٔ دانشگاه الزامی باشد.
